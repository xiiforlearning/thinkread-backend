# Этап разработки ThinkRead

Источники правды: CLAUDE.md (правила кода и принятые решения), Notion «ThinkRead → 📜
Документация» («Поверхностное ТЗ», «AI-агент и инструменты», «План разработки»), дизайн
«ThinkRead — кликабельный дизайн» и «ThinkRead Design System» (артефакты).

## Порядок

1. **Прочитать контекст**: раздел CLAUDE.md про этап, страницу плана в Notion, нужные артборды.
   Выписать решения заказчика, которые затрагивает этап (нормы, правила карточек, права).
2. **Домен** (`src/domain/<area>`): сущности с `@Check(enumCheck)` для enum-колонок, сервис с
   правилами, спеки на правила (jest, фейки вместо репозиториев как в `flags.service.spec.ts`).
   `domain/` не импортирует `infra/`. Ошибки — `AppError` с кодом из `error-codes.ts`.
3. **Миграция**: `pnpm typeorm migration:generate src/infra/db/migrations/<Name>`; руками дописать
   то, что TypeORM не умеет (CHECK при изменении enum, функциональные индексы). Проверить
   run → revert → run и отсутствие дрифта (скилл `verify`).
4. **AI** (если нужен): один принудительный tool-вызов на операцию, схема в `*.prompt.ts`,
   системный промпт без дат и имён (кэшируется), запись в `ai_usage`. Фейковый адаптер
   (`infra/ai/fake-llm.adapter.ts`) должен уметь ответить на новый инструмент — добавить
   ветку по имени инструмента и спек.
5. **API** (`src/infra/api`): тонкий контроллер, DTO с class-validator, сериализатор, Swagger
   `@ApiOperation`. Студент — `/me/*` через `StudentGuard`; персонал — `/admin/*` через
   `@Roles` и `AdminScopeService`. Прогнать скилл `api-smoke`.
6. **Mini App** (`frontend/`): типы в `src/api/types.ts` зеркалят сериализаторы, методы в
   `Api` + `HttpApi` + `MockApi` (мок должен уметь то же, что бэкенд), экран из компонентов
   дизайн-системы по артборду, хуки в `app/hooks.ts`. Прогнать скилл `screens`.
7. **Документация**: обновить CLAUDE.md (раздел этапа и «Current stage»), README (команды,
   эндпоинты, env), `.env.example`; при продуктовом решении — Notion.
8. **Проверка и коммит**: скилл `verify`, Conventional Commits (`feat(scope): ...`), пуш в
   рабочую ветку. В сообщении пользователю — что сделано, что проверено, что осталось.

## Критерии готовности

- Правило заказчика закодировано в одном месте (`globalConfig` или доменный сервис) и покрыто спеком.
- Эндпоинт возвращает `{ data }` / `{ error }` и проверен живым запросом.
- Экран совпадает с артбордом в обеих темах, демо-мок показывает тот же сценарий.
- Ни одной заглушки «TODO» без упоминания в итоговом сообщении.
