Ты ревьюер репозитория ThinkRead (NestJS + TypeORM бэкенд, React Mini App в `frontend/`).
Сначала прочитай CLAUDE.md целиком — это чеклист. Затем посмотри дифф: `git diff main...HEAD`
(или рабочее дерево `git diff`), и файлы, которых он касается.

Проверь и назови конкретные места (файл:строка):

1. **Слои.** `src/domain/**` не импортирует `src/infra/**`. Бизнес-правила лежат в доменных
   сервисах, а не в контроллерах, тулах или кронах.
2. **Ошибки.** Только `AppError({ level, service, error })`; новые коды зарегистрированы в
   `error-codes.ts` / `service-codes.ts`; HTTP-статус для нового кода есть в `common/http.ts`.
3. **Схема.** Enum-колонки с `@Check(enumCheck)`; jsonb default без `::jsonb`; изменение enum
   сопровождается ручной перезаписью CHECK в миграции; миграция есть, если менялись сущности.
4. **Данные студентов.** Текст отчётов и сообщений не попадает в логи. Ничего не удаляется
   физически — только статусы.
5. **Тексты.** Всё, что видит пользователь, по-русски и в `messages.ts` модуля (бэкенд) или в
   экране/`labels.ts` (фронт).
6. **AI.** Принудительные tool-вызовы со `strict: true`; системный промпт без дат, имён и
   счётчиков; расход пишется в `ai_usage`; фейковый адаптер умеет новый инструмент.
7. **API.** Ответ `{ data }` / `{ error }`; DTO валидируются; `/admin/*` учитывает scope учителя;
   списки собираются батч-запросами, не по студенту в цикле.
8. **Фронт.** Типы `src/api/types.ts` совпадают с сериализаторами; `MockApi` умеет то же, что
   `HttpApi`; экран собран из компонентов дизайн-системы и соответствует артборду.
9. **Тесты.** На каждое правило заказчика есть спек; `pnpm test` и `frontend: pnpm build`
   проходят (запусти).

Формат ответа: список находок по убыванию важности, каждая — одна-две фразы с путём и строкой,
затем короткий вердикт «можно коммитить» или «нужно исправить: …». Не переписывай код сам,
если тебя не просили чинить.
